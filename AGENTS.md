Later scoped ADR corrections and `reverse/port-status.md` take precedence over historical progress snippets below. In particular, ADR-0002 supersedes the old automatic standing-art height fit and projection assumptions.
- Write code and code comments in English; do not add Chinese source text.
- Declare every reverse-engineering-confirmed PAL ABI before or in the same change as its implementation. Add the reviewed contract to `reverse/abi/pal32.json` and regenerate `reverse/abi/pal32.h` and `crates/pal-vm/src/abi/generated.rs` with `python3 reverse/abi/generate.py`. - Native PAL exports, Game.exe VM extcalls, and Sena's host C API are separate interfaces. Preserve native 32-bit words at adapters; do not substitute Rust `bool`, `usize`, truncated integers, or arena handles for native ABI types. Check shared layouts and meaningful boundary cases, and run `python3 reverse/abi/generate.py --check` after ABI changes.

- Target game is Koikake (`恋×シンアイ彼女`) at the user's local game directory. Treat it as read-only. Do not unpack into the game directory.
- Preserve engine-generic PAL semantics. Do not hardcode this game's private variables or line text.
- `Blocked` in `crates/pal-script/src/extsig.rs` means the signature is not fully verified. It does not mean `pal-vm` lacks a handler.
- Run focused tests with `cargo test -p <crate>`. `cargo test --workspace --all-targets` fails in `pal-vm` `nls_config_fixture::startup_config_reads_system_ini_logical_size_before_vm_runs` because `testcase/SYSTEM.INI` is absent (the failure aborts later `tests/` binaries in the same run). `msprite_decodes_first_wmv_frame_from_fixture` is `#[ignore]` without `testcase/movie/opening.wmv`.

## Koikake boot facts

- `ARCHIVE.DAT` is `movie|bgm|mask|em|ev|ev2|etc|bk|se|system|face|voice|st|st2` and lives inside `data.pac`, not as a loose root file. `ResourceManager::bootstrap` searches the `data` base loose first, then `data.pac` (`crates/pal-asset/src/resource.rs`), so an unmodified game root boots. Regression test in `crates/pal-asset/tests/asset_fixture.rs`. The FHD releases add per-language lists (`ARCHIVE_CN.DAT` = `system_cn|etc_cn|movie_cn|update_cn`, `ARCHIVE_TC.DAT` = the same with `_tc`), kept inside `data.pac` in this install while their archives (`system_cn.pac`, `etc_cn.pac`, `movie_cn.pac`, `update_cn.pac`, and the `_tc` set) sit loose at the root. `ResourceManager::bootstrap_with_language` searches the language lists ahead of the base ones, so a localized archive shadows the Japanese archive of the same internal name (`system_cn` is what carries the title screen art and its buttons); a missing language list is non-fatal, and `--lang jp` passes `None`, which is `bootstrap` unchanged.
- There is no `ev2.pac` in this install. A missing search path stays non-fatal (`try_open_in_base` skips absent `.pac` files).
- Root `SYSTEM.INI` is Shift-JIS (engine default; strict decode, no lossy fallback). Logical size is 1280x720, which also matches the engine fallback. The engine reads `def_font_type`, `def_font_effect`, `add_fontname`, `ex_fontname` from the INI — it does not read the `font_size` key (size 28 is the code default). Game values: `DEF_FONT_TYPE = 4`, `DEF_FONT_EFFECT = 1`, `ADD_FONTNAME = default_font`, `EX_FONTNAME = font_ex`; the add/ex names coincide with the engine fallbacks. The FHD Chinese release under `testcase-cn/` has no loose root `SYSTEM.INI` — it sits in `data.pac` and the engine falls back to the archived copy — and there the logical size is 1920x1080 with `FONT_SIZE = 42` and `TEXT_DRAW_WIDTH = 1092`; `DEF_FONT_TYPE`, `DEF_FONT_EFFECT`, `ADD_FONTNAME`, `EX_FONTNAME` and the whole of `DEFAULT_FONT.DAT` are identical to this install.
- `Script.src` is Sv20, entry `0x1F8`, 4096 points, and the fixture walk finds 67,196 extcalls. Reference Game.exe slots 0..262 have 248 nonzero entries: 33 core handlers plus 215 high-primary aliases now routed through shared extcall dispatch. Aliases are generated from identical native table storage, not catalog names; direct forms advance 4 bytes and have no destination. Primaries 252/253 consume 2/1 operands and share timed/click wait behavior. This is dispatch coverage, not full handler parity. Unknown primaries block with `UnsupportedCommand`; known but unimplemented extcalls now report `ExtCallSkipped`. See `reverse/fx-vm-implementation.md` and the explicitly historical `reverse/vm-pal-shader-audit.md`.
- Headless play reaches the title and, after clicking GAME START, the first ADV line. Do not treat a multi-second `wait` as a hang. Harness: `sena --headless` with `--diagnostic-frames`, `--diagnostic-auto-advance`, `--diagnostic-click-when-hit-enabled`, plus per-frame logs and PNG snapshots.

## Implemented since the previous revision

- Movies: `movie_play` uses `na_mpeg2_decoder` and `wmv-decoder`, imported from `xmoezzz/siglus_rs` commit `5f358ef1360b0439e92aed2b749e8f25d8721954`, for MPEG and WMV frame-by-frame. MP4 playback is not established in the verified native profiles. The old MP4 claim came from an incomplete H.264 graph in the separate debug PAL_d.dll. Game's automatic suffix search is WMV/MPG/AVI, not MP4; see `reverse/movie-format-policy.md`. Effect-id-1 transitions crossfade the previous PAL frame instead of black. Loop points are honored; decoder reset/preroll restores `loop_start`, and `loop_end` restarts or finishes per loop mode.
- Text: ADV body text renders from the `DEFAULT_FONT.DAT` PAL bitmap font (parsed lookup table, Shift-JIS double-byte slots) when `font_type == 4` and glyphs exist; otherwise an external face when the release ships one, else the embedded `default.ttf`. There is no system-font path. `def_font_effect` applies a 1px outline. The wait mark renders (EX_FONTNAME sheet as animation frames, triangle fallback). `load_font` (9:15) now loads the requested DAT, `unload_font` (9:16) drops the bitmap independently, and `load_font_ex` (9:20) replaces the extended TGA sheet used for wait marks; failed extended loads clear the prior sheet.
- `FONT_EX.TGA` geometry is confirmed: the data.pac resource is 88x22, 8-bit grayscale with four horizontal 22x22 frames. The existing square-cell, `frame_count = width / height` path is correct for Koikake.
- Text language: `TextLang` (`--lang jp|cn|tc`, default `jp`, `crates/pal-vm/src/config.rs`) picks both the language archive list and the text field, and `--lang jp` reproduces the previous single-language path exactly. The FHD pool is UTF-16LE records joining one field per language with U+203B (`日文※简体※繁体`): `multilingual_text_table` recognizes it by its `$TEXT_LIST__` magic, `select_text_field`/`read_text_record_string` read field jp=0 / cn=1 / tc=2 (what the native `AdvCommandText0/1/2` variants select), and `FileDatLayout::detect` derives the `FILE.DAT` stride from its header count and probes UTF-16, so `read_file_slot_string` follows the same release. Text faces come from `game_font_faces`/`pick_face` (the face of `<root>/fonts/*.ttf` tagged for the language, first by path otherwise) or the caller's `--font-file`; when such a release also has the multi-language table, `PalFontSystem::set_bitmap_text_enabled(false)` keeps the loaded bitmap font out of body text — `set_type(4)` still succeeds and `measure`/`rasterize` stay on the same face as each other. The Android launcher carries the same choice per game (`LangOption`, `lang_utf8` through `sena.h` and the JNI entry points, defaulting to `cn`; iOS and macOS pass `nil`, unchanged). The release's own in-game 语言切换 row works through the same field: its handler stores the picked field in the script's settings and calls `set_language` (category 9 index 60, a different call from the PAL font type index 17 sets), which is handled as a live switch that re-typesets the parked ADV line. New backlog records now freeze the displayed strings at insertion, so existing records retain their language. Value 0 is what a fresh install stores, so it keeps the language its caller configured (`--lang` / launcher); once the player has picked 简体中文 or 繁体中文 in game, the script's stored field — persisted with `system_mem` — wins at boot. (Only the highlight needs the native engine's seeding of that stored field: with it unset the row still marks 简体中文, the script's default, while the text already follows the caller.) The Japanese script never calls index 60, so the `--lang jp` path is untouched. The neighbouring 文本字体 row works through the PAL font type instead: it only writes `mem_system[18]`, and the boot `set_language` (9/17) applies it. On a localized release that ships more than one face the type doubles as the face style — 0 (思源宋体) and 1 (思源黑体) — which `FaceStyle`/`pick_face_for` resolve from the file-name tags (`serif`/`sans`), keeping the language's own face when the release ships no face of that style; the original installs ship no such directory (`style_faces_enabled` is false) and keep the face boot selected, types 2/3 name no face, and like the native engine the change lands at the boot that applies the stored type rather than live.
- Audio: WMA decodes via `wmv-decoder`; `.MIX` playlists are summed/mixed; `BGM.CSV` loop points apply as sample-index loop regions (script start/end overrides win). `app_exec` stays a no-op returning 1 — it must not launch host programs.
- Operands: `MemDatIndirect` reads and writes resolve through the stored direct operand (Game.exe `0x42116b` semantics).
- Save/load: `save` writes original-layout `save/saveNNN.dat` (lock dword, title, mosaic, thumbnail prefix, resume text-command offset at 0x20C) with a `SENARSAV` portable snapshot appended. Thumbnail, mosaic, lock, and copy are implemented. Original-engine saves without the trailer resume by re-entering the script right after the text command recorded at 0x20C with the line rebuilt from the image's text value (0x12A3C) and a re-armed click wait (`import_original_save` in `crates/pal-vm/src/runtime.rs`). The resumable checkpoint refreshes at every parked ADV text command (`adv_wait_checkpoint_pending` is set by text extcalls too, not just `wait_click` — koikake's ADV body is a linear run of text commands), so saves made mid-scene resume at the current line instead of replaying from the savepoint. Portable snapshot format is version 10 (v8 freezes history strings, v9 preserves filter backups, v10 preserves Tips and BGV): button records carry cell size, selected source rect, and color (v4 fix for all-states-at-once buttons), version 5 adds the playing BGM list — a restore stops the outgoing scene's category-4 channels and replays the saved tracks at the top of the next `run_frame` (`replay_restored_bgm`), and version 6 adds each sprite's `native_projection`/`center_scale` — older snapshots restored standing CGs without the logical/1920 draw projection, so characters reappeared 1.5x too large and shifted (the "HiDPI offset" report) — and version 7 adds the ADV window alpha (`text_window_set_alpha`, which the script only re-sets when a scene or background changes, so a mid-scene restore used to come back with a fully transparent window base and the line drawn over the bare CG until the next scene; a snapshot without the field, and an imported original image, restore the window shown). Modal menus no longer advance the story: a button click parked on an ADV click wait suspends the wait (`suspend_wait_for_modal`) and re-parks it at the same PC when the menu gosub returns (`take_modal_wait_repark`), and the VM now receives the same button-consumed stripped input as the task system so menu clicks cannot complete work-process click waits.
- Settings: script-side global settings (SYSTEM screen toggles like 選択後スキップ/オートプレイ解除, stored in `system_mem` — kind 0x2, koikake uses `mem_system[53]`/`[54]`, defaults seeded once by point[4044] guarded on `mem_system[0]`) now survive menus and restarts. `memory_stack_push/pop` (category 9 indexes 21/22) no longer roll back `user_mem`/`system_mem`: the native push snapshots only a 0x4000-byte task work bank (ctx+0x1500), and the old portable model restored all three banks on pop, which silently reset every settings change when a menu closed. Cross-restart persistence goes to `save/sena_rs/system_mem.bin` (`SENARMEM` v1, trailing zeros trimmed), written by the `savesystemdata` extcall (category 10 index 25, which the script calls after settings changes) and loaded at boot. This persists more of `system_mem` than the native engine does (native system.dat keeps only the ctx+0x28278 0x800-byte slice = `mem_system[0xCE..0x2CE]` plus its own config block).
- Rendering gaps closed: `get_backbuffer` copies pixels; screen flash renders a fading quad; screen shake applies a decaying render-tree offset; history renders into a sprite and persists with saves (v8 freezes name/body/voice strings; face remains a raw handle); `graphic.dat` priority (lane × 134), placement offsets, scale, and tint/alpha lanes are applied in `sp_set` (scale skipped for 0/100 dwords). The backlog layout now follows the recovered native rules (`docs/original-save-format.md` 2026-09-29 section): records typeset at the ADV font size and body wrap width from `text_init` (koikake 28px/700px, pitch = size + arg1 = 38), name block stacked above the body (init arg4 = 40px), init arg7 = 16px record gap, bottom-up fill with top-overflowing records dropped, and one shared `HistoryLayoutCache` driving height/capacity/max-pos queries, rendering, and `history_update` hit-testing. `history_update` implements the native hover plate (0xFF4E4E4E behind the body block, text in the second init color, only for records carrying voice) and click-to-replay (stops all category-13 channels first, like 0x431A70). Not done: kinsoku line-head rules, the "…" overflow truncation, and the voice icon sprites from `history_set` (idx12). Sprite transitions now finish in one frame while a skip state is active (per-frame in `advance_transitions` and a forced 1ms duration in `sp_transition`), matching the effect_stop skip gate.
- Rendering backend: the interactive window renderer composites on the GPU through a real wgpu 29 backend (`crates/pal-vm/src/renderer/wgpu_backend.rs`) — ordinary textured-quad and native type-0 raster pipelines, per-texture nearest/linear bind groups (linear only when the software path would bilinear-smooth an upscale), half-texel UV inset to keep button cells from bleeding, non-sRGB surface format so blending matches the CPU compositor. The softbuffer compositor remains as fallback when wgpu init fails and can be forced with `PAL_RENDERER=software`. On the GPU path, diagnostic dumps (`--window-dump-frame-at`, `PAL_RENDER_DUMP`) are CPU-rasterized at logical resolution instead of read back. ADV text no longer re-rasterizes per frame: `sync_text_sprite` builds `AdvTextPanelCache` once per text change (base panel + fully rasterized text block + per-line char-x geometry) and the reveal clips those cached pixels at a fractional inside-the-glyph x limit, so the typewriter is a smooth wipe rather than per-character pops; identical frames are skipped via `presented_frame`, and the wait mark only recomposites when its 180ms animation frame changes.
- Web shell accepts a PAL game root (`data.pac` / `SYSTEM.INI` / `archive.dat`).
- Decompiler emits `reset_adv()` and explicit `dynamic_jump(...)` with tests.
- SOUND menu volume control works end-to-end. Four engine behaviors were reverse-engineered from the koikake script disassembly (points 1522/1526/1685/2415-2493) and are required together: (a) generic sprite extcalls accept packed button references `0x02000000 | group << 20 | index` — `sp_get_width`/`sp_get_height` resolve them through the button table, which is how menu scripts measure slider tracks; (b) `btn_slider_set(group, index, travel, axis, value)` positions the knob at `anchor + travel * value / 100` clamped to travel (the fifth argument is the slider value, not an enabled flag — BGM deliberately passes 250 to pin at max because its drag maps full travel to volume 0-40); (c) `btn_on_check(group, index)` returns `-1` once the mouse press ends and non-`-1` while the button holds the mouse (PAL buttons capture on push, tracked as `pressed_button`) — the slider drag loops poll `while btn_on_check(...) != -1`, so the old 0/1 latch deadlocked the menu in an infinite volume-applying loop, which was the "operating the SOUND page corrupts VM state" report; (d) `input_mouse_to_mem` (category 9 index 12) actually writes the live mouse position into the requested temp-mem slots — slider track clicks depend on it. Slider anchors are picked by the neighbour whose sprite sits closest to the knob's offset-zero rest position (`slider_offset` self-validation; plain proximity grabs the adjacent knob and lets the slider run off its track), drag snaps to integral percent, and `bgm_get_volume`/`se_get_volume` return configured percents rather than live (muted/ducked) group levels. `master/bgm/voice/se/voice_ex` volume percents persist through `save/sena_rs/system.ini` alongside the existing mute latches and `SENARMEM` system_mem bank, and boot calls `apply_persisted_audio_levels` after `AudioSystem::new` so restored settings reach Kira before any script volume extcall.
- SOUND menu right side is the per-character voice volume grid, fully script-driven, now rendering: SYSTEM.INI `[sound]` supplies the layout (`MAX_SOUND_UNIT=15`, grid origin/intervals), `Sound.csv` the character registry (`-1`/`-2`/`-3` rows map to `sound_unit_other/male/female`, flag 0 rows stay hidden until the script sets ENTRY_UNIT bits in `mem_system[61]`), and `vo_expos.csv` the per-slot coordinates. Three engine gaps hid it: `sz_buf` never wrote the caller's destination dynamic-string buffer (category 18 index 36 arg[3]) so `open_file` got an empty name and every downstream table read returned garbage; `wsprint` (category 18 index 9) did not parse `%02d`-style width specifiers nor atoi dynamic-string numeric arguments (`save_page%02d`, `save_btn_check%02d`, `sys_scut_menu%02d`, `sound_unit%02d` all load now); and `sz_buf`'s stray echo of its handle into `temp_mem[base+128]` clobbered the unit loop counter, so per-unit positions and names came out as string handles. `get_voice_ex_volume(slot)` / `set_voice_ex_volume(slot, volume, extra)` pop 1/3 args (observed counts) and keep per-character percentages in `voice_ex_volume_percent`, `voice_enable(slot, enabled, extra)` / `is_voice_enable(slot)` pop 3/1 and keep per-character mute latches in `voice_ex_enabled` (negative slots fall back to the global voice latch). Both maps persist in `save/sena_rs/system.ini`. At playback, `voice_play`/`text_voice` map the voice asset's `voNN` prefix through the `[sound] SOUND_UNIT_LISTFILE` CSV (`Sound.csv`; pseudo headers -1/-2/-3 catch vo99/vo98/vo97) to the unit slot and set the PAL channel volume to the per-character percent, so it composes with the group-wide voice volume.

## Current port corrections

Latest implementation: `reverse/fx-vm-implementation.md`; pre-fix evidence: `reverse/vm-pal-shader-audit.md`. The reverse reference and fixture differ: `reverse/PAL.dll` has 290 PE exports and Game.exe imports 215; `testcase/dll/Pal.dll` has 262 and koikake.exe imports 192. `PAL.sqlite` is the 288-export debug DLL. Keep addresses and effect-ID bounds scoped by build. Type-0 raster now has recovered parameters, start/stop/time progression, runtime calls, and CPU/wgpu/Switch drawing. Its WGSL is translated from compiled RASTER bytecode; RASTER_SW is a different program. Global raster captures the prefix on CPU before applying the effect. Radial blur math is corrected but its dispatch is unconnected; bicubic pass selection, full render modes/scene effects, FX save restoration, and Vita GXM shaders remain incomplete. See `reverse/vita-precompiled-rendering.md`.

See `reverse/port-corrections.md` for evidence and validation. Do not reuse old completion counts: `reverse/EXTCALL_CATALOG.md` now deduplicates explicit and automatic registry entries using effective lookup; statuses measure verification, not missing runtime handlers.

- Select renders options, blocks, and dispatches branches/reactions; push/pull modes are implemented. ## Continue here

Platform work: `platform/README.md` documents all hosts. Switch and Vita build real NRO/VPK packages using local devkitPro/VitaSDK and `nightly-2026-01-20`; hardware has not been tested. Console wrappers use `pal-vm` without default features and with `host-audio`, excluding winit/wgpu/CPAL. The host owns a separate PCM sink for its audio thread; stop and join the consumer before destroying that sink. Default desktop/mobile features and C ABI are retained. Console presentation currently uses the shared software compositor. Do not claim console GPU rendering or measured device performance.

1. Complete native save-image import/export: original sprite/history/window/sound wrappers and mirrored blocks remain incomplete. Native engine acceptance of written saves is not proved. Portable BGV/BGM restore restarts tracks rather than restoring exact playback position.
2. MP4 is explicitly rejected; do not enable it from the incomplete debug PAL_d.dll H.264 branch. See `reverse/mp4-native-audit.md`. Supported WMV/MPEG subsets do not imply all codec variants work.
3. Action timelines/text effect lanes need further native verification and rendering. History kinsoku, overflow ellipsis, and voice icon sprites remain absent.
4. BGV per-lane enable/auto-ducking remains incomplete. Exact fade curves and saved instantaneous fade gain are not mapped.
5. Sprite filter replay on replacement images and SIMD rounding parity are not verified. Select cursor warping/intermediate-state saves remain partial.
6. Dynamic font resources/type/effect are not part of portable snapshots. Cross-font scene restores can retain outgoing metrics; the extended sheet is implemented for wait marks rather than all native extended glyph rendering.
7. Host-specific verification remains necessary: no Windows/Android/iOS runtime certification follows from the macOS tests. Async key state uses delivered input events, not global OS polling.
